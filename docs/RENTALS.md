# 匿名按次租约（网页版）

入口：登录网站后，选择侧栏 **匿名租约**。沿用网站账号，无需另装客户端。

## 两类费用

- **服务费**：出借人填写，按申请时确认的价格记录。平台暂不代收、不结算、不标为已付款；没有收款码或匿名聊天。是否及如何线下结算需双方另行约定。
- **学校场地费**：查询新建的学校订单后获取实际金额，经出借人明确授权，从出借人的校园卡发起支付。它与服务费分开，绝不会把服务费叠加到学校付款请求中。

## 出借人使用

1. 在「登录设置」导入、验证自己的学校会话，填写预约联系电话。
2. 打开「匿名租约 → 我的出借授权」。填写服务费、单笔学校场地费上限、接受次数（1–20）、新单有效期（1–168 小时），勾选允许预约的场地。
3. 勾选本人授权，核对确认框中的**单笔上限、累计最高扣款金额和次数**，再发布。默认不勾选授权。
4. 发布后，其他用户在范围内申请时会直接尝试预约及校园卡付款，**无需逐单确认**。仅发布授权不会预约或扣款。
5. 随时下架以停止接受新单。**已接单仍按当时的授权处理**；下架不撤销学校订单，也不退款。

有效期约束新申请的接单时间；申请可选择未来 30 天内的日期，但仍须学校已开放且实时校验可预约。每份申请接单时消耗一次授权，未约成、超额或结果未知时也不自动补回次数，防止重复尝试扩大扣款范围。需要更多次数可明确发布新授权。

## 租用人使用

1. 注册并登录本站账号即可，不需要绑定自己的学校账号。
2. 在「找一个场地授权」选择匿名授权，选择场地与日期，查询学校实时可用时段。
3. 选择时段，核对显示的服务费与真实预约说明后提交。
4. 在「租约记录」查看结果。出现「已接单，等待后台处理」时可处理**同一笔**已接订单；不要另建一笔。
5. 「支付结果待核实」时，点击「向学校核实支付」。这是只读查单，不会重发预约或付款。学校确认缴费状态后才显示支付成功。

服务费展示不代表已收费或应自动退款。学校拒绝、会话失效、超额、余额不足或网络异常，都可能使预约或支付未完成；租约页不会披露出借人的余额或原始报错。出借人可在自己的「我的预约」「订单记录」「登录设置」核实。

## 隐私边界

租用人仅收到随机匿名编号、公开场地与时段、商定服务费、学校场地费及通用处理状态。API 不返回出借人的姓名、学号、网站用户名、电话、余额、Cookie、Token、学校订单编号、预约编号或本机路径。没有资料自由文本入口，避免意外把身份写进展示字段。

学校端仍由真实学校账号预约；网站运营者的服务器也必须保存账号与订单的关联以完成授权执行。**这是对其他网站用户隐藏身份，不是对学校或运营者匿名。** 能否由他人使用场地，仍以学校入场核验为准；本站匿名租约不是学校通行证。

## 执行与恢复

- `accounts.sqlite3` 新增 `rental_offers`、`rental_orders`。备份原有整个数据目录即可，无需另配数据库。
- SQLite 事务同时扣减授权次数、固定价格/限额并创建订单；每位租用人的请求编号唯一，重复请求返回原租约。
- 学校操作只在出借人自己的隔离进程中执行。浏览器不能指定任意账号；内部 `rental-*` 操作不在通用公开 API 白名单中。
- 提交预约/付款前先持久化处理状态。接口断开或服务重启后，已进入提交阶段的订单不自动重发。查单不付款；必要时由出借人核实学校原记录。
- 学校订单金额超出授权时只保留未付款订单，不继续扣款。未取得可靠的原订单时也不会猜金额或重新预约。
- 本版本不包含匿名聊天、服务费收款、学校取消/退款代理，亦不自动轮换账号来绕过学校的预约限制。

## 验证范围

自动化测试使用合成账号与模拟学校响应，覆盖跨用户权限、响应信息过滤、并发次数限制、重放、过期/撤回授权、账号绑定、动态金额上限、支付超时及最终查单。浏览器测试验证桌面和手机流程与无横向溢出。开发测试没有创建真实学校预约或扣款。
