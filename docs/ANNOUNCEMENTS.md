# 网站公告与管理权限

每次进入或刷新已登录页面时，如有已发布公告，会自动弹出模态公告，必须点击「我已阅读，继续使用」才能关闭；Esc 和点击背景不能跳过。已发布公告按置顶、更新时间排序，草稿与已下架公告不会强制弹出。

当前页面内已确认的同一版本不会因轮询反复弹出；每两分钟检查、从后台回到页面时检查，新增或更新的公告会再次弹出。如果正在核对预约或支付确认框，则等该框关闭后再展示公告，不覆盖确认操作。不干预服务器上已经启用的自动预约任务。

右上角「公告」可随时重新查看，首页欢迎区域也显示第一条公告标题。管理员先确认弹出的已发布公告，再进入公告板编辑或发布。

公告管理员可以新建、编辑、置顶公告。取消勾选「对用户发布」再保存，即保存草稿或下架；普通用户看不到草稿和已下架内容。标题最多 80 字、正文最多 4000 字，均为纯文本，不执行 HTML 或脚本。并发编辑旧版本会提示刷新，不覆盖另一位管理员的新内容。

## 授权管理员

只有能操作服务器的部署者可以授予公告管理权限，不采用“第一个注册者自动成为管理员”。在服务器中执行：

```sh
python -m badminton_reservation.announcements --data /data --username 已注册的网站用户名
```

该命令只授权管理公告，不允许读取其他用户的学校凭据或操作其他用户的账户。管理员仍使用普通网站登录及改密流程；所有公告写操作均校验管理员身份、Origin 和 CSRF，前端隐藏按钮不是权限边界。

公告、管理员名单保存在原 `accounts.sqlite3` 的独立表中，随服务器 `/data` 一起备份。管理员的初始随机密码应单独交给站点拥有者，不提交进仓库。

## 本轮性能调整

- 场地探索默认实时查询当前选中的一块场地。其他场地显示「点选查询」，不会把未查到的数据标为空闲。点击「查询全馆」仍可一次读取整个场馆。
- 首次进入时，把目录刷新与当前场地查询合并到一次后台操作，共用一次会话验证；手动查询、预约和付款仍按原逻辑校验身份。提交预约前再次核实占用。
- 当前场地每 60 秒更新，超过 90 秒的状态不能直接预约。不跨用户共享会话或学校业务响应缓存。
- 网页版在浏览器支持 WebP 时发送无损图片版本，并用 `Vary: Accept` 区分缓存，旧浏览器保留 PNG。两张图片合计由 3,650,716 字节降至 2,875,790 字节（约 21.2%），已逐像素比较相同。

2026-09-20 的单次诊断中，健康接口服务端处理约 0.1 ms、复用连接网络往返约 179 ms；两张原图各需约 1.2–1.3 秒下载。容器内存约 159 MB/1 GB，采样时未记录 CPU 限流。学校公开页面的请求约 0.65–1.28 秒，但这不能代表带登录的预约接口耗时。优化减少了网络请求和首屏传输量，并不保证学校接口总能快速响应。
